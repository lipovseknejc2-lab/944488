# Atelier: rules for Claude Code

We work on **one app only: Atelier**, the team-work app (notes, projects, groups, chat, focus). It is one self-contained HTML file that works offline on an iPhone and is published on GitHub Pages.

- **Live:** https://lipovseknejc2-lab.github.io/944488/atelier/
- **Source:** `src/atelier/` (read `src/atelier/NOTES.md` first)
- **Published folder:** `atelier/` (`index.html`, `sw.js`, `manifest.webmanifest`, icons)
- **Design:** `DESIGN.md` (read it before any visual change)

The repository also contains other apps (the site root and the other folders). **Do not touch them**, unless Nejc explicitly asks.

**Atelier Plugins** (`src/hub/`, published at `atelier-plugins/`) is Atelier's desktop hub for building plugins: sign in, a builder license (everyone gets one during the test period), a dashboard, the studio (nodes or code), a test bench, public plugins and sending to phones by QR codes. Sign in has an illustrated tour of objects only (`scenes.js`, one 9-second timeline written by `KF`). The account is shared with Atelier (localStorage `atelier-account`: only an id and the first name), so sign in can continue as the Atelier account. There is no license step: the License tab claims the builder license (a thumbs-up character, `cheerScene`), holds codes for up to three computers, and lists what a license changes. Your groups (`groups.js`) reads Atelier's save on the same computer (read only) or an account link scanned from a phone (`ATL1`), and makes private edits for one group. Node points count what you build, and Settings change the accent, surface, canvas and code. It shares the plugin engine with Atelier through `src/plugkit/pk.js` (plus `src/plugkit/vendor/` qrcode-generator and jsQR). Build it with `python3 src/hub/build.py` and copy `src/hub/dist/hub.html` to `atelier-plugins/index.html`. Its service worker clears only `aplug-` caches. Read `src/hub/NOTES.md`.

**Mintora** (`src/mintora/`, published at `mintora/`) is a second app Nejc asked for: a desktop web app for digital products, with Mintora Blueprint for plugins and designs. Read `src/mintora/NOTES.md` before working on it, test it with `bash src/mintora/tests/run.sh`, and keep it separate from Atelier.

## The four rules that matter most
1. **Never simplify, remove or downgrade.** Keep every feature, screen, animation, drawing and detail. Changes add or improve. A rewrite must do everything the old version did.
2. **Never make the design worse.** Follow `DESIGN.md` exactly. New screens must look like they were always part of Atelier: same tokens, glass, line icons, gesture characters, handwriting accents and motion. When unsure, copy an existing Atelier component.
3. **Never lose data.** Saved data: localStorage `atelier-v1` and `atelier-backup`, plus IndexedDB `atelier` (files, drawings, voice). Never rename them. If the data shape changes, write a migration so old saves keep working.
   The profile (first name, surname, student or working, school or work, email) is encrypted with AES-GCM 256 in `S.me.vault`; only the first name stays in plain text. The key is a non-extractable CryptoKey in IndexedDB under `key:profile` (or localStorage `atelier-key` where IndexedDB is blocked). Never delete or rename the key, never write the profile in plain text, and use `storeProfile()` to change it. Encryption is never mentioned in the interface.
4. **Test everything, publish, then give the link.** Every update ends with the live link.

## How Atelier is built
- The modules in `src/atelier/` are joined in this order by `build.py`: `../plugkit/vendor/qrcode.min.js`, `../plugkit/vendor/jsqr.min.js`, `../plugkit/pk.js` (the shared plugin engine), `art.js` (icons, characters, avatars, posters, clock), `core.js` (state, storage, knots meter, router, UI kit), `people.js` (bot teammates, onboarding), `today.js` (Today, ledger, quick panel, voice), `focus.js`, `reset.js` (guided reset), `notes.js` (notes as boards: parts, arrows, sketches, motion, backgrounds), `flow.js` (the Flow tab and materials), `chat.js` (chat sections, direct messages, people), `groups.js` (groups as servers: categories, channels, roles, verification), `plugins.js` (plugins in groups, scanning, reactions), `projects.js` (tasks, ideas, notes, files, drawing boards, inspiration, table and chart), `study.js` (flashcards, exams, study goal, subjects), `pulse.js` (the Pulse motivation check, insights, nudges), `school.js` (timetable, grades and goals, practice quizzes, study plans), `widgets.js` (chat widgets and their editor), `rewards.js` (themes, frames, quotes, profile, collection), `you.js` (You, posters, settings, boot). `shell.html` holds all CSS and the page shell.
- `python3 build.py` writes `dist/atelier.html` with the fonts (Newsreader, Instrument Sans, Caveat) embedded. Never edit `dist/` or `atelier/index.html` by hand.
- Today, rebuilding from `src/atelier/` reproduces the live `atelier/index.html` byte for byte.

## Things that must keep working
- **Navigation** is an in-memory router (`go()`, `redirect()`, plus a click handler for `a[href^="#"]`). It must not depend on the address bar, because phone previews block it. Use `go('page')`, never `location.hash=`.
- **Storage** goes through `LS` (falls back to memory when blocked) and IndexedDB (`IDB`). Wrap new storage in try/catch.
- **Knots** are usage tracking: call `use('action')` for every new action and add it to `ACT` in `core.js`. They appear only on the You page.
- **Ledger:** important actions call `led(kind, text, {ref})` so they show on Today.
- **Bots:** teammates reply in chat, vote on ideas and pick up tasks (`people.js`). New collaborative features should let bots react too (add lines to `LINES` for new shared kinds).
- **Sharing:** anything can be shared into any conversation with `shareTo(att)` or `sendMsg(c, text, att)`. Shared kinds live in `ATT` (`chat.js`): note, project, file, photo, doc, focus, day, agenda, progress. Photos and files are blobs in IndexedDB under `c…` keys; `dropBlob()` frees them when the last message using them is deleted.
- **Sheets** that start something (recording, timers) register `onSheetClose(fn)` so closing the sheet in any way stops it.
- **Focus timer** keeps real end times (`endAt`). After the phone was locked or the app closed, `catchUp()` replays every switch from the moment each phase really ended and credits only real focus time. Never reset an overdue timer to now.
- **Keep awake:** while a focus session exists (focus, break, paused, Deep mode, guided reset) `keepAwake()` keeps the screen on: the Wake Lock API, plus on iPhone a hidden, silent 1.5 KB looping video (`#awake`, no sound track) because Home Screen apps on many iOS versions ignore the lock. It is re-taken on every tap, on return to the app and every few seconds, and released when the session ends. `S.settings.awake` (Settings and the Alerts sheet) switches it off. Call `keepAwake()` instead of `wakeOn()`/`wakeOff()` in new focus code.
- **Sounds** go through `audioCtx()` (the audio session is `ambient`, so music keeps playing) and `audioIdle()` suspends it after the last tone, so the iPhone never keeps an audio session open.
- **Class names on full-screen layers** (`#zen`, `#rst`) must be unique: a short name like `sw` is already the colour swatch and once shrank Deep mode to a 30 px box. Prefix new state classes (`zswap`, `rst…`).
- **Deep mode** (`enterZen()`): true black, dim text, only timer and phase, screen kept on with the Wake Lock API, a small pixel shift each minute. `S.focus.zen` brings it back after a reload.
- **Guided reset** (`reset.js`, `openReset()`): a two-to-three-minute break routine of one breathing technique, two stretches (three on a long break) with a "Just breathe" pause (only the circle) between them, and a 20-second far look, shuffled so it never repeats the last mix (`S.settings.lastReset`). It has a breathing orb and a stick figure posed by joint angles (`rigPaths`) that eases every frame. It uses Deep mode black. It shows as a card on Focus during breaks and as a quiet pill (`#zRs`) in Deep mode. Saved in `S.resets`. The figure has real proportions (shoulders, hips, elbows, knees, hands, feet, curved spine), a front and a side view (`side`), stands on the floor by itself, and uses `rIK` for hand positions. Soft tones (`RSND`, muted with `S.settings.resetSound`) mark each step, the moment to look back after the far look, breath switches and the end.
- **Alerts:** `notifyFocus()` shows a system notification only when Atelier is in the background (needs permission; on iPhone the app must be on the Home Screen). For a locked phone, `calAlerts()` hands the phone's calendar an .ics file with an alert at every switch. A web app on GitHub Pages cannot schedule its own notifications or show a lock-screen live timer.
- **Two spaces:** `S.settings.space` is `student` or `work` (switched on the You page). Both have the tabs Today, Focus, Flow, Chat, You; Flow (Study flow or Work flow) holds notes, agenda, materials and study or projects. Each space has its own Flow contents, Today summary (`spaceHero()`), quick actions (`ACTS`) and wording. New features should fit both, or show only where they belong.
- **Tab bar** is built once (`nav()`); afterwards only the active tab, the sliding highlight and the badge change. Never rebuild it on a new message, or it jumps.
- **Themes:** every theme only sets design tokens (`SKINS` in `rewards.js` generates the CSS). Every new feature must use the tokens (`--bg`, `--card`, `--text`, `--accent`, `--line`, `--fill` and so on), never raw colours, so it looks right in every theme, light and dark; the tests open every screen in every theme. New themes can be added over time, always priced above the ones before.
- **Knots** use `KSCALE` (8): a normal full day is about 1,600 knots. Themes and frames unlock at all-time totals and are never spent; the top theme is over a million (about two years). `fixData()` scales older saves once.
- **Logo (Thread):** `MARK_A` (the symmetrical A), `MARK_B` (the clay thread crossbar) and `MARK_DOT` (its end) in `art.js` are the only source; the splash, posters, widgets and `atelier/icon.svg` plus the PNG icons must always use the current mark.
- **Groups are servers** (`groups.js`): each group has categories and channels (`g.cats`, `g.chs`), roles (`g.roles`, `g.mroles`, checked with `can(g,perm)`), a picture and a banner (IndexedDB `g…` keys), and is private or official (`g.type`, `g.org`, `g.verify`: pending until verified; only Atelier's own Community group is verified). Every channel is a chat in `S.chats` with `kind:'group'` and `ch`, so messages, widgets, pins, files and bots work everywhere; `onChat(c)` says whether a chat is on screen. Channel types live in `CHT` (talk, announce, files, gallery, projects, notes, ideas, events, all). `gFixAll()` migrates old groups (Main, #general, #files, Owner and Member) and runs in `fixData()` and `boot()`. Plugins run per group as `g.plugins` instances (see Plugins). Chat has rounded section tabs (`chatTabs()`): Messages (direct chats and a groups strip), Groups, People.
- **Plugins** (`plugins.js`, engine `PK` in `src/plugkit/pk.js`): the library is `S.plugins` (plus `PK.STARTERS`: Welcome, Coins, Spotlight, File helper); groups run instances `g.plugins=[{id,pid,on,store}]`. Events (join, message, keyword, command, reaction, daily, timer, file, role, install) go through `plugFire`; runs of one plugin take turns (`_plQ`). Node plugins run in the page through the same API as coded ones; coded plugins run only in the sealed sandbox (`PK.runCode`: an iframe with no origin, no network, a worker inside, two seconds at most). Plugins return actions that `plugAct` applies (post as the plugin, react, pin, roles, copy files, make channels, notices). Plugin messages have `from:'pl'` and `pl:{id,name,pic}`. Plugins arrive by QR codes (`plugScan`, several codes collected in any order), pasted code, a file, a `#plugin=` link, or the hub's inbox (localStorage `atelier-plugin-inbox`, same site). Typing `/` in a channel lists the commands, and the composer and the command chips glow (`PK.fmt` wraps `/commands` in `.cmdt` and `#channels` in `.chm`). Plugin messages are widgets (`PK.plCard`: picture, name, title, big value, rows with bars, text, a tone colour, a look: glass, solid, outline or banner, and a size); the `card` node and `a.card({title,value,unit,text,tone,style,size})` send them, and `PK.guess` turns plain leaderboards and short stats into widgets too. Plugins can open designed pop-ups (`popup` node, `a.popup()`, `PK.popHtml`, `plugPop`).
- **Private plugins and credit:** plugins carry `rules`, `howto`, `tags`, `cat` (`PK.PCATS`) and, when built from another plugin, `base` (the credit that always shows, `PK.credit`). A private plugin has `priv:{gid,gname}` and works in that group only; `from` names the plugin it edits. Without a builder license a private edit carries `lock` (the blocks and wires it came with stay, the name and picture stay, at most `PK.LIMITS.max` new safe blocks, no new bots, no code). `PK.guard(edit, from)` checks this in the hub and again in Atelier (`plugCheck`) before `plugApplyPriv` swaps it into the group and keeps its values. Publishing to Public plugins and using a plugin in many groups need the license.
- **Bots** (`pl.bots`, at most 8): each bot has a name, a picture, `scope` (`group` or `channels` with `chs`), on or off, and nodes or code. `PK.runAll` runs the plugin and then each bot that works in the event's channel, sharing values. Bots post as themselves (`m.pl.bot`, tag Bot), show in a hideable Bots section of the member list (`botRows`, `S.settings.hideBots`), and can be switched off per group (`inst.botsOff`, `plugBot`). Bot blocks: Has words, Language is (`pkLang`), Blur the message (`m.mod`, tap to read, managers can show it again), Warn someone, Read the file, Sort files, Show a pop-up. In the hub a bot has its own tab and canvas in the studio, and can be copied to another plugin or as `ATB1.` code.
- **Reactions:** `m.rx={key:[who]}`; ten drawn reactions in `PK.REACTS` (love, like, haha, wow, sad, star, done, idea, coin, spark) plus any keyboard emoji (`u:` keys). Press and hold a message to react; teammates react now and then; plugins react too.
- **Icons:** the home screen icons are flat and matte (charcoal, cream A, clay thread, a dot grid and a focus ring), drawn from the mark; the hub's mark ends its thread in a plug.
- **Notes are boards** (`notes.js`): keep `n.body` in sync with `syncBody()` after every board change, and keep `ensureBoard()` as the migration for old notes. The note widget is the only place the unfold icon is used.
- **Materials** (`flow.js`): files in `S.materials`, blobs in IndexedDB under `m…` keys.
- **Widgets** (`widgets.js`): Atelier's branded live cards in chat, with size, font and surface the user picks and that are remembered per kind. Anything shared as a card should be a widget kind.
- **One design language:** new screens use the widget grammar and the glass material described in `DESIGN.md` (tiles, `.lab` label rows, big tabular numbers, `--glt`/`--gl-hi` glass, `--spring` presses).
- **Pulse** (`pulse.js`, `S.pulse`): the 40-second motivation check (wheel of feelings with intensity rings, energy, eight statements) scored with Temporal Motivation Theory and Self-Determination Theory; the day's percentage is a weighted mean that favours the latest check. Feeling in the Palette opens it; the quick feeling check-in stays as "Just log a feeling".
- **School** (`school.js`): classes in `S.study.classes` fill the agenda by themselves (`classItems()`, virtual, never saved as agenda items); grades in `S.study.grades` with goals and a scale (1 to 5 by default); quizzes saved per deck; study plans in `S.study.plans` own their agenda items.
- **The Palette** (quick panel): floats over pages and is never part of the layout. It is open by itself only on Today; elsewhere it is a handle.
- **No emojis** anywhere in the text. Use line icons from `art.js`.
- **Offline:** `atelier/sw.js` may only delete caches starting with `atelier-`.

## Testing before every publish
Nejc's preference: for a normal update, run a quick test of the changed feature (a focused Playwright script on an iPhone-sized viewport, light and dark, no script errors). Run the full suite below only when he asks for a big testing cycle.

`bash src/atelier/tests/run.sh` builds Atelier and runs everything: features (282 checks), phone taps in three setups (204 checks), stress and crash (heavy data plus 400 random taps), groups (96 checks in light and dark plus desktop: migration, private and official groups, every channel type, roles, members, verification, the Everything feed, votes, widgets in channels), notes and Flow (96 checks in light and dark: parts, arrows that route around parts, sketch, motion, undo, migration, materials, the note widget in chat), plugins (112 checks in light and dark: starters, commands, coins, roles, files, coded plugins in the sandbox, QR codes, scanning, the inbox, reactions, the shared account, private edits and their checks, bots, blurring, pop-ups, the account link), the hub (88 checks: sign in and the tour, one account, claiming the license, codes, node points, settings and surfaces, studio, nodes and code, bots, the bench and its widgets, private edits with limits, Your groups, the public browser, sending and importing), the hub and Atelier together (QR codes drawn, photographed and read both ways, the inbox), focus mode (60 checks: switches in normal and Deep mode, screen kept on, quiet audio, light and dark), and offline (7 checks). It needs node with playwright (`npm i playwright`) and python3.
- All tests must pass with zero errors. Add checks for every new feature to `tests/feat.js` and `tests/phone.js`.
- Look at screenshots of every changed screen on an iPhone-sized viewport, in light and dark, and compare them with `DESIGN.md`. If it looks plainer or less finished than before, it is not done.
- No screen slower than about 100 ms with normal data. Memory flat. Animations smooth.

## Publishing and finishing
1. `cd src/atelier && python3 build.py && cp dist/atelier.html ../../atelier/index.html`
2. Raise `CACHE` in `atelier/sw.js` (for example `atelier-v1` to `atelier-v2`) so phones update.
3. `git pull --rebase`, commit on `main` with a clear message, `git push`.
4. Wait until `gh run list -L 1` shows the Pages deployment completed successfully.
5. Reply to Nejc with a short summary of what changed and the link **https://lipovseknejc2-lab.github.io/944488/atelier/**, plus "open it once online and it updates".

English. Short, warm, plain sentences. No emojis.
